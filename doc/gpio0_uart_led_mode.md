# GPIO0 的 UART / LED 模式

XM / GD 两版固件的功能代码相同，差异只来自 1KB 头里的一个字节。本文是工具菜单 4「uart/led」与菜单 1/6 展示的依据。

## 结论

| 字段 | 位 | 取值 | 含义 |
|---|---|---|---|
| `0x105` | bits 7:6 | `0x40`（=1） | **UART**，115200 调试串口；GD 底包当前值 |
| `0x105` | bits 7:6 | `0x80`（=2） | **LED**，GPIO0 忙闲闪烁、无串口输出；XM 底包当前值 |
| `0x107` | bit 7 | 0 / 1 | 输出电平基础值 `0x10` / `0x30` |

四个 `FIRMWARE/*.bin` 实测：`GD25Q80@USON8.bin` 的 `0x105=0x40`，XM 系三份均为 `0x80`；`0x107` 全为 `0x00`。头 `0x100–0x10F`（两版只差第 6 字节）：

```
XM: 02 00 00 00 00 80 00 00 00 00 00 00 32 39 30 33
GD: 02 00 00 00 00 40 00 00 00 00 00 00 4e 41 36 31
                   ^^^^ 0x105
```

`0x105` 只有 bits 7:6 被读取（低 6 位未见独立引用），`0x107` 只有 bit 7 被使用。改这两个字节**不需要重算任何校验**：客户参数区 `0x000–0x3FF` 不在 DWORD0 奇偶与 DWORD31 XOR 的范围内。

## 模式判定

开机时读 `0x105 >> 6` 分派：

| bits 7:6 | 行为 |
|---|---|
| 0 | 无 UART/LED 动作 |
| **1** | 初始化串口控制器，波特率 `0x1C200` = 115200；GPIO0 归 UART TX/RX |
| **2** | LED 忙闲闪烁：固件忙 → GPIO0 点亮，空闲 → 延迟约 1 秒熄灭 |
| 3 | 保留分支 |

两版固件都保留 mode 1 的完整 UART 初始化代码，因此 `0x105` 双向切换（`0x80` ↔ `0x40`）在代码层面都成立，差异纯粹来自头字节。

## 易混淆项

- **`MODE_SPI` 不是 `0x105`**：另有一套运行时引脚复用枚举（`RESET/UART/SPI/GPIO/MONITOR/LED`），用于临时把同一组引脚交给 SPI 控制器。FW Download / FW Commit 写 SPI Flash 期间会切到 `MODE_SPI`，**这段时间串口日志必然中断**；这是引脚复用，与 `0x105` 的常驻模式无关。
- **开了 UART ≠ 日志内容丰富**：`0x0C9` bit6 是诊断命令 / SMART 更新开关，XM 置位、GD 清零；GD 虽是 UART 模式，诊断类日志反而比 XM 少。
- **静态成立 ≠ 真机可用**：XM 板 GPIO0 物理上很可能接的是 LED，把 `0x105` 改成 `0x40` 只会让灯不闪，未必有串口输出。在缺少 UART 日志 / 直连调试、每次验证都要拆板重刷的条件下，不要靠连续盲改去猜结果。
